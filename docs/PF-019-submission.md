# Pathfinder submission package

Pathfinder helps self-directed software-development learners connect a career goal and their current skills to a practical next learning activity.

Learners often know the role they want but struggle to decide what to practice next. This proof of concept turns self-reported skill descriptions into a preliminary assessment and an ordered, curated starter path.

## Official challenge alignment

Theme: **Learning That Stays With You**.

Primary challenge: **Track 3 — Guidance, Pathways & Opportunity**. Self-directed learners struggle to translate career ambitions and current skills into practical next learning actions. Pathfinder addresses the guidance/pathways part through a suggested starting activity; employment outcomes and opportunity integrations are not implemented.

Secondary design alignment: **Track 2 — Engagement & Staying in the Learning Journey**. Clear next actions and manageable practice steps are intended to reduce uncertainty about continuing. Long-term retention, engagement improvements, and learning outcomes have not been measured. This is an **invention-sprint proof of concept**, not a production launch. No learner interviews or research findings are claimed.

## Delivered proof of concept

Career goal → current technical skills → explicit Gemini disclosure and consent → AI-assisted classification → curated learning path → recommended next action.

- Goals and current skills are validated and persisted in PostgreSQL; React confirms the saved values.
- One current-skills submission is permitted per goal.
- For “Become a backend developer” (case/outer-whitespace insensitive), Gemini classifies Programming language, SQL, Git, HTTP/API concepts, and Automated testing as identified, not_identified, or uncertain.
- Rails validates all five classifications before deriving catalogue-version-1 activities. Activities are curated and language-flexible, not generated by Gemini.
- Paths omit identified categories from immediate gaps, invite clarification for uncertain categories, and provide one integrated exercise if every category is identified.
- The recommended next action equals the first ordered step. Completion evidence is suggested, not submitted or evaluated.
- PF-018 provides a separate offline developer evaluation tool with human-authored expectations and simulated actual classifications.

## Architecture

React/TypeScript → Vite `/api` proxy → Rails API → PostgreSQL and Google's Gemini API. Docker Compose supplies local development services. Gemini credentials remain backend-only; curated path derivation adds no provider request or persistence. Setup and API contracts are in the [root README](../README.md), [backend README](../backend/README.md), and [frontend README](../frontend/README.md).

## Known limitations and privacy

Localhost-only proof of concept; no production deployment, authentication, authorization, goal ownership enforcement, or rate limiting. A goal ID does not prove ownership; browser consent is not server-side access control. Do not expose it as a production multi-user service.

Learner text is sent to Google's Gemini service only after explicit UI consent; use synthetic information and avoid confidential data. Provider availability and quotas may change. Request/SQL description redaction and generic errors protect application logging; never share keys or resolved environment configuration.

Classifications are interpretations, not verified competence, mastery, or job readiness. Assessments and paths are transient and not restored after refresh. Retrieval/editing, history, learner-project evaluation, proficiency scoring, and advanced/adaptive paths are deferred. The next action does not record completed work.
